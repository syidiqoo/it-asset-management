# Taste
- Communicates in Indonesian (Bahasa Indonesia) and expects replies/explanations in Indonesian. Confidence: 0.7
- Prefers minimal, uncluttered UI: dislikes stacking summary/stat cards ("semakin banyak desainnya semakin jelek") and asks to remove them, replacing them with a lighter integrated pattern (e.g. an inline filter bar merged with the table). Also dislikes decorative/hero areas cluttered with action buttons ("jelek sekali") — expects an informational banner/hero to stay purely informational (title/subtitle/image only), with extraneous props, imports and variables cleaned up when the elements are removed. Confidence: 0.8
- Wants clear separation of concerns between pages/features: each page has one job (e.g. "Manajemen User" only fills in people into existing positions, "Manajemen Department" only manages the structure that those positions come from). Confidence: 0.6
- Requires additions to be strictly additive: never remove or break existing working features when implementing something new (stated emphatically, e.g. "jangan pernah menghapus fitur lain yang sudah bagus"). Confidence: 0.9
- Likes to see features running live locally rather than only reading a summary/build result — asks for the app to be started on a local dev server (and the data seeded) so he can try it himself, and explicitly asks to be shown the result live ("perlihatkan kepadaku di live"). Confidence: 0.75
- Prefers the least invasive fix that solves the problem in place (e.g. keep file uploads in `public/uploads` with validation, rather than relocating them and rearchitecting access) — favors change that is simple and localized over broader restructuring. Confidence: 0.5
- Prefers a dark-dominant visual theme: near-black (Ubuntu-black) canvas with a single warm accent color (orange, e.g. Ubuntu #E95420) used sparingly, with dark as the default appearance. Also wants an explicit light/dark theme toggle so the user can switch (state persisted across reloads, no flash on load) — a hard-coded dark-only look is not enough. Confidence: 0.65
- Likes styling to be anchored to a concrete, well-known reference design and asks for it to be followed closely — e.g. explicitly "follow ubuntu.com style", naming primary/secondary button colors, hover states, and layout/heading scale as things to match. Confidence: 0.65
- Wants button components to expose distinct, explicitly defined variants with clear hover states (separate primary / secondary / outline / ghost styling, using dedicated hover color tokens rather than just an opacity tweak on the base color). Confidence: 0.5
- Design taste leans enterprise-SaaS/minimalist: clean cards, thin subtle borders, medium corner radius, minimal shadows, high contrast, generous whitespace, bold headings; explicitly dislikes excessive gradients, glassmorphism, neon colors, heavy drop shadows, over-rounded UI, and crowded layouts. Confidence: 0.65
- When he hands over detailed written design notes/specs, he expects them to be read carefully and followed precisely ("baca notes ini dengan teliti") instead of being loosely interpreted. Confidence: 0.55
- For new data-entry modules, expects existing master data to be reused instead of duplicated: the assigned person is picked from the existing User data ("seperti biasa usernya diambil dari data user") and dependent fields like Department derive from that user, not entered twice. Confidence: 0.65
- Enumerable attribute values should be modeled as managed master data with their own dedicated CRUD menu/page (e.g. a "Package" list with add/edit/delete) rather than free-text fields, and seeded with the example values he names. Confidence: 0.6
- Specifies table columns exhaustively and literally ("untuk tabelnya hanya ada ...") — expects the table to show exactly the listed columns, with no extra columns added. Confidence: 0.55
- Prefers sidebar navigation organized by importance: only primary workflows at top level (Dashboard, Data Aset, SIM Card), with secondary/master-data sections (User, Department, Kategori Inventaris, Package SIM) collapsed under a single dropdown parent ("Pengaturan"). Confidence: 0.5
- Prefers simple inline expand/collapse menus over popup/portal-based menus ("dropdown sederhana saja bukan popup") — sub-menus should open in place with a rotating chevron, not as a floating overlay. Confidence: 0.6
- Wants to review and approve the implementation plan before changes touch the database/schema; he reads the plan and corrects assumptions (e.g. that CLS Domestic/Roaming are numbers), so plan-first is expected for migrations. Confidence: 0.5
- Cares that new UI features stay lightweight and don't burden the app ("yang penting bagus dan tidak membebankan aplikasi") — expects cheap rendering (pure CSS over JS, avoid extra DB queries, no heavy assets) rather than a rich/animated showpiece. Confidence: 0.6
- Leaves the aesthetic specifics of a new feature to the agent ("ukuranya menyesuaikan saja, yang penting bagus") as long as the result looks good and matches the existing design language — he specifies intent/constraints, not pixel details. Confidence: 0.55
- Context-dependent: previously wanted user-visible content admin-configurable from a settings page (dashboard banner edited via "Pengaturan → Banner"), but later reversed this for content he judged low-value, asking to remove the banner editor and make the banner fixed/hard-coded — the "make it configurable" expectation applies only to content actually worth managing, not as a default. Confidence: 0.4
- Prefers grouping static image assets into a dedicated subfolder (e.g. `public/img/`) referenced by a clean path instead of scattering them at the project root or `public/` root, and wants only a single canonical copy (old duplicates removed). Confidence: 0.6
- Prefers full-bleed background images rendered with `next/image` in `fill` mode (`object-cover`, dark gradient overlay so text stays legible) rather than a plain `<img>` or CSS background. Confidence: 0.5
- Prefers cutting a feature entirely when it seems low-value rather than building/maintaining configurability for it ("sepertinya tidak terlalu penting") — expects the unused page, form, action, validation schema, DB model/migration, sidebar entry and seed data to all be removed together. Confidence: 0.6
- Cares about production readiness: before handing an app off to production, expects an end-to-end security/exploitability review that proactively hunts for gaps and bugs (auth bypass, upload exposure, session issues, rate limiting, headers). Confidence: 0.6
- Values durable written documentation of the app's features, asking for a simple user-facing guide (e.g. a `PANDUAN.md`) that explains the existing features. Confidence: 0.5
